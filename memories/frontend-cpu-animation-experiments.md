# Frontend CPU and animation experiments

TermDeck's Chrome process was observed using roughly 30–35% CPU while sitting on an idle terminal. The investigation used a fixed stock-project terminal without tab switching so activity generated by the test itself would not distort the result. Disabling unrelated status scans, snapshot work, polling, terminal repair features, and xterm addons had little effect. Disabling the continuously animated sidebar state produced the largest reduction, while retaining the WebGL terminal renderer was substantially cheaper than forcing xterm onto its DOM renderer.

The original working-title wave animated `background-position`, and one fallback SVG spinner animated `stroke-dashoffset`. Both require repeated painting rather than compositor-only updates. The sidebar animations were rewritten so every CSS keyframe now changes only `transform` and `opacity`. Active animated elements receive narrowly scoped `will-change` hints, all animations pause when the browser document is hidden, and a shared `IntersectionObserver` pauses terminal-row and group-header animations outside the visible sidebar viewport. The observer runs only when visibility boundaries change and does not add polling or a JavaScript animation loop.

An animated GIF processing beacon was tested as an alternative. It reduced observed Chrome CPU to roughly 5% or less, but it was harder to integrate cleanly with theme colors and animation state, and the visual tradeoff was not worth maintaining a separate path. The optimized CSS implementation measured around 25% CPU, down from roughly 30–35%, while preserving the preferred live title wave and dot behavior. We settled on the CSS implementation and removed the GIF and all temporary performance-bisect settings.

Terminal rendering remains controlled by the Tall terminal setting. Its WebGL mode computes a row budget from the browser's maximum texture size and device pixel ratio, then uses WebGL when the machine can support the requested terminal height. Its DOM mode uses the full configured DOM row count without WebGL. There is no separate WebGL switch because it could contradict the selected tall-terminal mode and make the reported mode misleading.

The settled behavior is therefore: live sidebar status updates and animations are always enabled, visible animations use compositor-friendly properties, offscreen and hidden-page animations pause, and the Tall terminal selector is the single renderer policy control. Future CPU work should start from repeatable whole-browser process measurements and should avoid adding persistent diagnostic switches unless a feature remains genuinely optional.
